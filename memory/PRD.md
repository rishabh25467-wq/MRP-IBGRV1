# PRD - SAP BOM Viewer / Materials Hub

## Original problem statement
Extend the existing SAP BOM viewer application: Production Plan page (OMS Open-PO Demand feed), 2-Tier MRP, Microsoft Entra ID (Azure AD) SSO, Supplier Portal for external vendors, PO Creation automation, Inbound STO Receipt page (groups multiple SAP delivery lines), native SAP Business ByDesign Custom Business Object (ABSL) replacing Playwright for multi-line STO Outbound Deliveries. Most recent asks (Sep 2026): Supplier Portal entity restriction + GRN Site/Warehouse auto-derivation + JDE theme visual pass, and a Production Confirmation bug (Net Weight wrongly mandatory for hardware-kit BOMs).

## Architecture
- `/app/backend/`: FastAPI + MongoDB. Key files: `server.py` (routes, incl. `_pick_rm_item`/`_compute_scrap_calc` scrap-weight logic), `supplier_shipment_service.py` (vendor shipment lifecycle), `sap_po_client.py` (PO cache/buyer entity), `sap_wip_clearing_client.py` (site->company RI/RT mapping), `sap_valuation_client.py` (pricing - has an open bug, see backlog).
- `/app/frontend/src/`: React. `GrnApprovalPage.jsx` (internal GRN approval), `pages/supplier-portal/*` (vendor-facing: Dashboard, Shipments, Login, Signup, Pending).
- Theme: JDE Enterprise ERP (`/app/design_guidelines.json`) - Chivo headings, IBM Plex Sans body, JetBrains Mono data, #004B87 primary, #0E7C86 header teal, #EAECF0 table headers, grid-bordered zebra tables. `tailwind.config.js` defines `fontFamily.heading/sans/data`.

## What's been implemented (Sep 2, 2026 session)

Warehouse auto-preselects a `-QC` suffixed warehouse when available. Backend also validates site_id server-side in `prepare_approval()` (400 if mismatched).

- **Supplier GRN "PO not found in SAP" - REAL ROOT CAUSE FOUND + FIXED (Sep 2, 2026, this session)**: user reported PO 29086 was genuinely Released/Ordered in SAP, yet the Playwright GRN automation (`sap_playwright_supplier_pgr_service.py`) kept saying "PO not found... check its status". Root cause was a chain of THREE separate, real bugs in the automation, all found via live read-only reproduction and fixed in order:
  1. `_search_po_exact`'s base-view dropdown selector was hardcoded to the text "Open Purchase Orders", but this SAP session's actual remembered variant was "Due and Overdue Purchase Orders" (a real, narrower query that silently excludes valid POs like 29086) - per user's explicit instruction ("do not search with due and overdue filter, search in all purchase orders"). Fixed by targeting the dropdown's stable SAPUI5 ID suffix `[id$="-defaultSetDDLB"]` instead of matching current text (a naive `.sapMSlt` class selector was tried first and was ALSO wrong - it matched the unrelated global-header search-category selector, not the base-view one).

Once search worked, clicking the found row (`row.click()`) landed on the "Supplier Name" hyperlink cell (row center) and navigated into an unrelated Business Partner screen instead of just SELECTING the row - "Post Goods Receipt" (a list-toolbar-only button) was then never findable. Fixed by clicking the row's empty first `<td>` (selection-indicator column) instead.
  3. The "Create Inbound Delivery and Goods Receipt" screen's own Line Items grid takes longer to load than the old fixed 4s wait - fixed by waiting for its "Loading..." text + the blocking overlay to clear first.
  4. `_fill_line_actual_quantities` used ElementHandle-only methods (`query_selector_all`) on Playwright Locator objects (from `.locator(...).all()`) - always raised `'Locator' object has no attribute 'query_selector_all'` the moment it got this far (never triggered before since bugs 1-3 always failed first). Fixed to use Locator-consistent `.locator()/.count()/.nth()`. ALSO found the "Actual Quantity" cell holds 2 inputs (qty field + a UOM combobox) - fixed to target `input:not([role="combobox"])` only.

- **Warehouse Movement negative-stock bug - REAL ROOT CAUSE FOUND + FIXED (Sep 2 2026)**: live-checked shipment MU7DE2's actual on-hand stock via `sap_inventory_client.get_inventory_detail()` after its GR posted - found the received stock sits under SAP stock_status **"Inspection"** at P1-RM (this material's own SAP QM/Inspection Plan routes all PO receipts there), not "Not Assigned"/blank. `_post_goods_movement_for_items()` in `supplier_shipment_service.py` always left `InventoryStockStatusCode` blank (assuming plain/"Not Assigned" stock) - P1-RM only had 1.0 EA under that blank bucket for G12LW (causing "Negative stock not permitted", asked for 2) and ZERO for G12FW (causing "No inventory items found"). This does NOT contradict the existing Aug 28 2026 finding in the same docstring (that forcing a stock-status CHANGE via this API fails) - this is a plain relocation of stock that's ALREADY at Inspection status, so it must be moved AS Inspection status on both ends, not blank. Fixed with a new `_resolve_source_stock_status()` helper that live-queries `sap_inventory_client` at call time to find which status code the source area's balance for that exact material/qty actually sits under, and targets that (falls back to blank if nothing matches). Threaded `sap_inventory_client` through `finalize_goods_receipt()`/`retry_goods_movement()` and both `server.py` call sites. Live-verified: MU7DE2's retry-movement now returns `sap_movement_status: "posted"` for both G12LW and G12FW; SAP inventory confirms 2.0 EA of each moved from P1-RM(Inspection) to P1-QC(Inspection).
- **"Output posted but Task still open in SAP and Emergent" - REAL ROOT CAUSE FOUND + FIXED (Sep 2 2026, live incident Lot 71425)**: reproduced live via `find_lot_by_id('71425')` - `confirmation_finished: true` (output fully posted, 320/320, frozen forever once set) but `task_finished: false` (Task never closed). Root cause: `confirm_reporting_point()` chains a SEPARATE standalone `finish_task()` call right after the ReportingPoint update succeeds, but never wrapped it in try/except - when `finish_task()` raised a SOAP fault, it propagated straight out as an exception, discarding the fact the ReportingPoint update had ALREADY succeeded (irreversible). `_confirm_production_inner`'s exception handler then reported total failure and never logged anything (confirmed zero history entries for Lot 71425). The user's retry then failed with "Changes in task or lot not permitted; confirmation complete indicator set" - SAP correctly rejecting a second attempt to resend already-frozen fields. Fixed: (1) `finish_task()` call now wrapped in try/except so a failure is preserved as a normal partial result, not an uncaught exception; (2) new endpoint `/production-confirmation/finish-task` (mirrors `/retry-wip-clearing`) that calls ONLY the standalone Finish Task action - safe regardless of ReportingPoint state; (3) `ProductionConfirmationPage.js`'s Confirm dialog now detects this exact stuck state (`confirmation_finished=true && task_finished=false`) and swaps the quantity form for a single "Finish Task" button, so this can't be walked into again. Live-verified: Lot 71425 now shows `task_finished: true`, `life_cycle_status_label: "Finished"`.

## Known constraints / learnings
- RI (RAY INTERNATIONAL) sites today: P1, P8 (also nominally P1W/W1 per SITE_TO_COMPANY map, but those have zero live inventory so never appear in `list_known_sites`). RT (RADISH TECHNOLOGIES) = everything else, including P2W.
- QC warehouse does not exist at every site - the "default to QC" behavior is a soft pre-select, never a hard requirement.
- Never trigger a real "Approve & Post to SAP" click/call on a real PO outside of a deliberate, user-approved live test - it queues a real Playwright job against production SAP.
- Scrap/by-product Net Weight enforcement (`_pick_rm_item` in server.py) must NEVER guess an RM by "biggest quantity" for an item with no prior Net Weight precedent - only known raw-stock keywords (Iron/CR/SS/Alu/Brass/Copper family incl. Rod/Pipe/Angle/Channel/Mesh/Ingot) or an already-configured `component_master.net_weight_kg` may trigger the requirement.
- `SITE_TO_PERMANENT_ESTABLISHMENT_UUID` (sap_valuation_client.py) is the only place this site->UUID mapping lives - reuse it, don't rediscover, if extending site-specific pricing to other screens.
